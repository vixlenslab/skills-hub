O mapa do tesouro

Antes de sair usando tudo, entende o ecossistema. São três mundos diferentes com poderes diferentes.

💬 Claude Chat
O claude.ai que você já conhece. Conversa, análise, criação de conteúdo, pesquisa. Simples. Mas tem uns segredos (Projetos, Artifacts) que a maioria ignora.
⌨️ Claude Code
Claude que vive no seu terminal. Lê os seus arquivos, edita código, roda comandos. É tipo contratar um dev que trabalha na sua máquina. Assustador? Só no começo.

Claude Code configurado para trabalho em equipe e fluxos de negócio. Agents com papéis, skills de time, contexto compartilhado. Pensa como um escritório inteiro de IAs.

Fundamentos

Como Claude pensa

Entender isso é o maior unlock que existe. A maioria nunca para pra pensar nisso.

Claude é literalmente amnésico por padrão

Cada nova conversa começa do zero absoluto. Claude não lembra que você existe. Não lembra do seu negócio. Não lembra que você prefere respostas curtas. Nada. Por isso você fica reexplicando as mesmas coisas toda hora.

A solução? CLAUDE.md, Projetos e plugins de memória. Veremos cada um. Mas por enquanto: a razão das suas respostas serem genéricas é que Claude não te conhece.

Contexto = qualidade da resposta

Claude não é mágico. Ele responde baseado no que você deu pra ele. Pouco contexto = resposta genérica. Muito contexto relevante = resposta cirúrgica.

❌ Pergunta sem contexto
"Escreve uma copy pra mim"

Claude vai escrever algo genérico que poderia ser qualquer coisa pra qualquer empresa.
✅ Pergunta com contexto
"Sou CMO de uma startup de software pra óticas. Público: oculistas pequenos. Produto: gestão de estoque. Escreve headline pra landing page."

Agora sim.

As camadas de instrução (quem manda em quem)

Claude segue instruções em ordem de prioridade. Da mais fraca pra mais forte:

CamadaOnde ficaQuando vale

CLAUDE.md do projeto./CLAUDE.mdSó nesse projeto

Sua mensagem agoraA conversaPrioridade máxima
TL;DR do mindset: Claude é um estagiário brilhante com amnésia total. Quanto mais contexto você der, mais ele brilha. Sua missão é criar sistemas que guardem esse contexto automaticamente.
Chat

Claude Chat Básico

claude.ai — você já usa, mas provavelmente não usa os recursos que realmente importam.

Projetos — o recurso que muda tudo no Chat

Projetos são pastas de conversa com contexto persistente. Você configura uma vez, e todas as conversas dentro do projeto herdam esse contexto. Acabou de reexplicar teu negócio todo dia.

O que colocar num projeto:

  • Arquivo de contexto: O que é a empresa, produtos, público, tom de voz
  • Instruções fixas: "Sempre responde em português", "Não usa gerundismo", "Tom direto"
  • Documentos de referência: Brand guide, briefings, tabelas de preço
  • Exemplos de output: Textos que você gosta, emails que funcionaram
Analogia: Projeto é como contratar um funcionário e dar pra ele um onboarding completo. Em vez de repetir tudo pra cada conversa nova (estagiário novo todo dia), você faz o onboarding uma vez e pronto.

Artifacts — o canvas do Claude

Quando Claude gera código, HTML, SVG ou documento longo, aparece um Artifact ao lado. Você vê o resultado renderizado, pede alterações direto nele, e itera sem perder o histórico. É o jeito certo de fazer qualquer coisa visual ou técnica no Chat.

Memória automática

O ícone de livro no Chat — Claude pode salvar informações entre conversas. Você pode pedir: "Lembra que eu prefiro respostas sem introdução" ou "Salva que meu produto é X". Funciona, mas é menos confiável que CLAUDE.md.

Modelos — qual usar?

ModeloQuando usarVelocidade
Opus 4.8Tarefa difícil, análise complexa, código desafiador. Quando qualidade importa mais que velocidade.☕ (vai buscar café)
Sonnet 4.690% das tarefas. Ótimo equilíbrio. Padrão inteligente.⚡ rápido
Haiku 4.5Respostas rápidas, resumos, tasks simples.🚀 muito rápido
Regra prática: Começa com Sonnet. Só muda pro Opus se o Sonnet errar ou simplificar demais. Haiku só pra coisas que não precisam de raciocínio.
Code

Claude Code Intermediário

O Claude que vive no seu terminal e tem acesso real à sua máquina. Parece assustador. Na prática é libertador.

A diferença que muda sua vida

No Chat, você copia e cola código manualmente. No Code, Claude lê seu arquivo, faz a alteração, roda o teste e te fala o resultado. Você só aprova ou rejeita. É a diferença entre ter um assistente remoto e ter alguém sentado do seu lado.

Instalando e iniciando

npm install -g @anthropic-ai/claude-code

claude                    # abre sessão interativa
claude "faz X no projeto" # modo rápido, processa e sai
claude -p "faz X" --model opus  # escolhe modelo

O que Claude Code consegue fazer

  • Ler qualquer arquivo do seu sistema
  • Editar código, criar arquivos, deletar (com confirmação)
  • Rodar comandos no terminal (npm, git, python, o que for)
  • Fazer commit, criar branch, abrir PR no GitHub
  • Pesquisar na web, acessar APIs via MCP servers
  • Spawnar outros Claudes pra trabalhar em paralelo

Permissões — o segurança na porta

Claude pede confirmação antes de coisas destrutivas. Isso é bom. Você pode afinar o que ele pode ou não fazer sem pedir:

// .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git *)",
      "Read(**)",
      "Edit(src/**)"
    ],
    "deny": ["Bash(rm -rf *)"]
  }
}
Não faça isso em produção: --dangerously-skip-permissions desliga todas as confirmações. Claude vai fazer tudo sem perguntar. Use só em ambientes controlados e isolados.

Modos de operação

Interativo
Você conversa, Claude age. Perfeito pra desenvolvimento, análise, tarefas que precisam de vai-e-vem.
Não-interativo (-p)
Manda um prompt, recebe resposta, sai. Perfeito pra scripts, CI/CD, automações.
Pipe (|)
cat arquivo | claude -p "revisa". Integra com qualquer pipeline Unix.
Background (--bg)
Roda como agente em segundo plano enquanto você faz outra coisa.

O Code lê automaticamente

Quando você abre uma sessão num diretório, Claude já leu:

  • O CLAUDE.md do projeto e dos diretórios pai
  • O status do git atual
  • A estrutura de arquivos quando relevante

Não precisa ficar explicando a estrutura do projeto toda vez. É por isso que o CLAUDE.md vale tanto ouro.

Cowork

Claude Cowork Intermediário

Claude Code turboalimentado para trabalho em equipe. Agents com papéis definidos, skills de negócio, contexto compartilhado.

A diferença em uma linha

Code é você e Claude. Cowork é você, Claude e um ecossistema inteiro de agents especializados trabalhando juntos. Pensa como um escritório onde cada agent tem um papel.

Setup

/setup-cowork   # guia de configuração inicial

Ele pergunta seu papel (dev, designer, marketing, etc), instala as ferramentas certas e conecta com seus sistemas.

Skills exclusivas do ecossistema

/standup
Gera relatório de standup baseado no que você fez na última sessão. Chega de escrever update manual.
/make-plan
Cria plano estruturado com etapas, dependências e estimativas. Antes de codificar, planeja.
/timeline-report
Cronologia do que foi feito no projeto. Útil pra briefings e retrospectivas.
/pathfinder
Mapeia um codebase que você nunca viu. Essencial ao entrar em projeto legado.
/weekly-digests
Resumo semanal do que foi feito, automático, baseado na memória acumulada.
/oh-my-issues
Analisa issues do GitHub e sugere prioridade, tamanho de esforço e próximos passos.
Skills

Skills Intermediário

Imagine que você pudesse dar ao Claude um "modo especialista" pra qualquer área. É isso que skills fazem.

O que é uma skill na prática

Uma skill é um arquivo SKILL.md com instruções específicas. Quando você digita /copywriting, Claude carrega aquele arquivo e passa a operar como um copywriter especializado — com frameworks, exemplos, regras de tom, o que evitar. Não é mágica: é contexto certo na hora certa.

Analogia perfeita: Skill é tipo instalar um "modo" no Claude. /caveman = modo econômico de tokens. /design-taste-frontend = modo designer de agência. /marketing-plan = modo CMO estrategista. Você escolhe qual "chapéu" o Claude coloca.

Como instalar

# Pacote de skills do marketplace (recomendado)
npx skills add usuario/repositorio

# Skill individual via git
git clone https://github.com/usuario/skill.git ~/.claude/skills/nome

# Exemplo — humanizer (remove padrões de IA do texto)
git clone https://github.com/blader/humanizer.git ~/.claude/skills/humanizer

Como usar

/copywriting      # ativa modo copywriter
/humanizer        # ativa humanizador de texto
/marketing-plan   # ativa planejador de marketing
/design-taste-frontend  # ativa modo designer premium

Onde ficam

LocalEscopoQuando usar
~/.claude/skills/nome/Todos os projetosSkills que você usa em qualquer contexto
.agents/skills/nome/Só este projetoSkills específicas do projeto

Criar sua própria skill

Qualquer coisa que você repete — um estilo de escrita, um processo de análise, um template — vira skill. Estrutura mínima:

---
name: minha-skill
description: Quando e por que usar esta skill
allowed-tools:
  - Read
  - Edit
---

# Você é [papel especializado]

Quando ativado, você [comportamento específico].

## Regras
- [regra 1]
- [regra 2]

## O que nunca fazer
- [anti-padrão 1]
Atalho: Use /skill-creator — ela guia você passo a passo na criação de uma skill nova. Você descreve o que quer, ela gera o arquivo.

Quando NÃO usar skill

Pra tarefa única e simples, não precisa. Skill vale quando a tarefa é recorrente (você vai fazer isso várias vezes) ou precisa de conhecimento especializado que Claude não tem por padrão.

Plugins

Plugins Intermediário

Se skill é um chapéu, plugin é um armário inteiro. Skills + hooks + MCP + agents num bundle só.

Plugin: claude-mem

O plugin de memória persistente. Claude observa tudo que acontece na sessão e injeta contexto relevante na próxima. É como ter um assistente que lembra tudo automaticamente.

npx claude-mem start      # liga o worker de memória
# worker fica rodando em http://localhost:37777

/learn-codebase           # aprende o repo inteiro (~5 min, opcional)
/mem-search "auth"        # busca o que já foi feito/decidido
/standup                  # gera update do que você fez
/timeline-report          # cronologia de atividades
Como funciona: Worker fica em segundo plano, registra observações (arquivos lidos, erros, decisões). Próxima sessão, injeta automaticamente o que é relevante. Tudo em ~/.claude-mem na sua máquina — não sai do seu computador.

Plugin: caveman

Muda completamente o estilo de resposta. Resposta enxuta, sem firula, ~75% menos tokens de saída. Você vai longe mais rápido no limite de uso.

/caveman         # modo padrão
/caveman lite    # um pouco menos agressivo
/caveman full    # sem artigos, sem filler (modo atual)
/caveman ultra   # mínimo absoluto, quase telegrama
stop caveman     # volta ao normal
Modo caveman em ação:
Normal: "Claro! Fico feliz em ajudar com isso. O problema que você está descrevendo é provavelmente causado por..."
Caveman: "Bug no middleware. Token usa < não <=. Fix:"
MCP Servers

MCP Servers Avançado

Model Context Protocol. Basicamente: você dá ao Claude acesso a sistemas externos — GitHub, banco de dados, Google Drive, qualquer API.

O que são na prática

MCP servers são processos rodando em paralelo com o Claude que expõem ferramentas. Claude chama essas ferramentas exatamente como chama Read, Edit ou Bash. A diferença é que você define o que elas fazem.

Analogia: Claude nasceu com mãos (Read, Edit, Bash). MCP server é você dar ao Claude um braço novo com ferramentas customizadas. "Agora você tem acesso ao GitHub." "Agora você consegue consultar nosso banco." "Agora você lê o Google Drive."

Configurar um MCP server

// .claude/settings.json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "seu_token_aqui" }
    }
  }
}

MCP servers mais úteis no dia a dia

ServerO que dá pro ClaudeCaso de uso
server-githubCriar PRs, issues, ler reposDev workflow completo
server-filesystemAcesso a pastas fora do projetoArquivos em outros diretórios
server-postgresConsultar e escrever no bancoAnálise de dados, migrations
Figma MCPLer designs, extrair tokensDesign → código
Gmail MCPLer e rascunhar emailsAutomação de email
Google Calendar MCPVer e criar eventosGestão de agenda
Instale com critério: MCP server tem acesso real ao sistema que ele conecta. Se é o GitHub server, Claude consegue criar, editar e deletar repos. Só instala de fontes confiáveis e revisa o que o server pode fazer.
Hooks

Hooks Avançado

Automações que disparam em resposta a eventos do Claude Code. Claude edita um arquivo? Roda prettier. Claude inicia sessão? Injeta contexto.

A regra de ouro: hooks vs skills

📚 Use SKILL quando...
É uma orientação que deve ser seguida. Um estilo, um padrão, contexto especializado. Você ativa com /nome. Opcional.
⚙️ Use HOOK quando...
É algo que deve acontecer sempre, sem você precisar pedir. Formatar código, bloquear ações perigosas, logar eventos.

Eventos disponíveis

EventoQuando disparaExemplo de uso
SessionStartClaude iniciaInjetar contexto, ativar modo caveman
UserPromptSubmitVocê envia mensagemPré-processar, adicionar contexto ao prompt
PreToolUseAntes de qualquer ferramentaBloquear ações perigosas
PostToolUseDepois de qualquer ferramentaFormatar código editado, notificações
StopSessão terminaGerar relatório, limpeza

Hook na prática: prettier automático

// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit",
      "hooks": [{
        "type": "command",
        "command": "npx prettier --write $CLAUDE_FILE_PATHS"
      }]
    }]
  }
}

Agora toda vez que Claude edita um arquivo, prettier roda automaticamente. Nunca mais código mal formatado saindo de uma sessão.

Memória

Sistema de Memória Intermediário

O problema: Claude tem amnésia. A solução: vários sistemas diferentes pra persistir contexto. Aqui estão todos.

Os 4 jeitos de dar memória ao Claude

1. CLAUDE.md
Arquivo de texto que Claude lê automaticamente. O mais confiável. Você escreve, ele lê toda sessão. Melhor pra contexto permanente.
2. Projetos (Chat)
No claude.ai, Projetos têm contexto persistente. Arquivos, instruções e conversas ficam conectados. Perfeito pro Chat.
3. Auto-memória
Claude Code salva memórias em arquivos quando você pede. /memory abre o arquivo. Pra preferências e contexto de projeto.
4. claude-mem plugin
Worker que observa tudo e constrói base de conhecimento buscável. O mais poderoso, requer setup do worker.

Auto-memória — os 4 tipos

Quando você pede ao Claude pra lembrar algo, ele cria um arquivo de memória categorizado:

TipoO que salvarExemplo
userSeu perfil e preferências"Prefere respostas diretas sem introdução"
feedbackCorreções e confirmações"Não usa comentários óbvios em código"
projectEstado do projeto, decisões"Projeto usa React 19, deploy na Vercel"
referenceOnde encontrar informações"Docs da API estão em /docs/api"
Como pedir: "Lembra que eu prefiro respostas sem introdução", "Salva que o projeto usa Tailwind v4", "Guarda que o deploy é feito com esse comando".

Onde ficam as memórias

Arte do prompting

A Arte do Prompting Intermediário

Isso aqui vai ser difícil de ouvir: a maioria das respostas ruins que você recebe é culpa do prompt. Boas notícias: dá pra aprender.

A fórmula que funciona

Contexto → Objetivo → Restrições → Pedido → Formato

Na prática

❌ Que a maioria faz
"Escreve um email de vendas pro meu cliente"

Claude vai inventar um cliente, um produto e um tom. Vai ficar genérico demais pra servir.
✅ O que funciona
"Contexto: Software de gestão pra óticas pequenas. Cliente: Diego, oculista, 2 lojas, viu demo ontem. Objetivo: marcar reunião de fechamento. Tom: profissional mas direto. Máximo 150 palavras. Assunto: máximo 6 palavras."

5 técnicas que mudam o jogo

1. Mostre, não descreva

Em vez de descrever o estilo que quer, cole um exemplo. "Escreve no estilo deste parágrafo: [exemplo]" é mil vezes mais eficaz que "tom informal mas profissional".

2. Diga o que NÃO fazer

Claude tem vieses. Proibir explicitamente funciona: "Não use 'transformar', 'elevar', 'jornada', 'potencializar'. Não comece frases com 'Além disso' ou 'Portanto'."

3. Peça o formato antes de responder

"Responde neste formato:
HEADLINE: [texto]
SUBHEADLINE: [texto]
CTA: [texto]
JUSTIFICATIVA: [uma linha por item]"

4. Peça pra pensar antes

"Antes de escrever, identifica os 3 principais riscos
desta abordagem e como contornaria cada um. Depois escreve."

5. Itere precisamente

❌ Vago
"Melhora esse texto"
"Faz ficar melhor"
"Não gostei, refaz"
✅ Cirúrgico
"Mantém a estrutura, torna o tom 30% mais direto, corta todos os advérbios e remove a última frase"

Anti-padrões clássicos

Você dizClaude entendeO que fazer
"Melhora isso"Muda qualquer coisa aleatóriaEspecifica o que melhorar e como
"Escreve sobre X"Escreve Wikipedia sobre XDefine ângulo, público, objetivo e tamanho
"O que você acha?"Resposta genérica e diplomáticaPerguntas critério específicas
"Cria algo criativo"Criativo segundo Claude, não vocêDê referências, mostre exemplos, defina o que é criativo pra você
CLAUDE.md

CLAUDE.md Intermediário

O arquivo mais impactante que você pode criar. Claude lê automaticamente toda sessão. É o onboarding permanente.

Por que isso é o maior unlock do Code

Sem CLAUDE.md: você passa os primeiros 5 minutos de toda sessão explicando quem você é, o que é o projeto, como funciona a stack. Com CLAUDE.md bem escrito: Claude já sabe de tudo quando você digita a primeira mensagem.

É sério: Escrever um bom CLAUDE.md global (~/.claude/CLAUDE.md) é o investimento com maior ROI que existe no Claude Code. 30 minutos agora economiza horas por semana.

Template global (~/.claude/CLAUDE.md)

# Sobre mim
Sou [seu papel]. Trabalho principalmente com [tecnologias/áreas].
Nível técnico: [iniciante/intermediário/sênior] em [áreas].

- Respostas diretas, sem introdução tipo "Claro! Fico feliz em ajudar"
- Português brasileiro sempre

- Código com comentários só quando realmente necessário

- Não adiciona features que não foram pedidas
- Não refatora código fora do escopo

Agentes

Exército de Claudes Avançado

Claude pode criar outros Claudes pra trabalhar em paralelo. Coisas grandes ficam rápidas quando você tem um exército.

A ideia por trás

Tarefas grandes têm partes independentes. Em vez de fazer uma por uma, o Claude principal delega a subagentes que rodam em paralelo. No final, sintetiza tudo. É como gerenciar uma equipe em vez de fazer tudo sozinho.

Exemplo real: "Audita todos os 50 componentes React deste projeto" sem agentes = Claude lê um por um, leva horas. Com agentes = Claude spawna 10 agentes, cada um audita 5, termina em 10% do tempo.

Agentes disponíveis no caveman

AgentePropósitoQuando usar
cavecrew-builderEdições cirúrgicas em 1-2 arquivosTypo, rename de variável, pequena função
cavecrew-investigatorLocalizar código (só leitura)"Onde é definido X?" — retorna file:line
cavecrew-reviewerReview de diff/branch"Revisa esse PR" — saída comprimida

Agentes gerais

AgentePara que
ExploreBusca ampla no codebase. "Encontra todos os lugares que usam X"
PlanArquiteta implementação antes de codificar
code-reviewerReview independente — perspectiva diferente do agente principal
Custo real: Cada subagente tem contexto próprio e consome tokens. Use pra tarefas que genuinamente precisam de paralelismo. Não spawna agentes pra coisas simples — é canhão pra matar mosquito.

Dicas de produtividade que realmente importam

  • Uma sessão = uma tarefa. Misturar assuntos polui o contexto e piora as respostas.
  • /compact quando a sessão ficar longa. Comprime histórico, mantém qualidade.
  • CLAUDE.md bem escrito > qualquer prompt. 30 min investidos hoje = horas economizadas por semana.
  • Itere rápido e preciso. Claude trabalha melhor com refinamentos específicos do que com pedidos vagos de melhoria.
  • Verifique output crítico. Claude pode errar — especialmente em código novo, cálculos e fatos específicos. Não confie cegamente.
  • Quando Claude errar, corrija e peça pra lembrar. "Isso tá errado por causa de X. Lembra essa regra." Constrói memória útil.
